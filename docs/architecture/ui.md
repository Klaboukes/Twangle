## UI state model
```kotlin
enum class TunerMode { AUTO, CHROMATIC }   // in :core:settings, saved by name

sealed interface TunerUiState {
    data object PermissionRequired : TunerUiState
    data class  Error(val reason: TunerError) : TunerUiState
    data class  Listening(val mode: TunerMode, val tuning: Tuning, val a4Hz: Float, val lockedString: Int?, val notation: Notation) : TunerUiState   // no usable signal
    data class  Detected(
        val mode: TunerMode,
        val tuning: Tuning,
        val a4Hz: Float,               // concert pitch in use (A4 calibration)
        val notation: Notation,        // how note names are written
        val noteName: String,          // target note in that notation, e.g. "E", "D♭", "Re"
        val octave: Int,               // e.g. 2
        val frequencyHz: Float,        // smoothed
        val cents: Float,              // smoothed; Auto: unwrapped distance to the string, Chromatic: about ±65
        val targetString: Int?,        // index into tuning, Auto mode only
        val lockedString: Int?,        // string the user locked (then also targetString), else null
        val inTune: Boolean,           // ≤ 5 cents for ≥ 300 ms, released past 7 (Precise: ≤ 2, past 3)
        val hint: TunerHint?,          // the steady hint line: in tune, tune up or tune down
        val reception: Float,          // 0..1 how well the note is heard (ReceptionTracker), drawn not written
        val tip: ReceptionTip?,        // too soft / too noisy / too loud, held steady (Listening has it too)
    ) : TunerUiState
    data class  StrumCheck(            // strum check on, guitar mode (see Strum check view)
        val tuning: Tuning,
        val notation: Notation,
        val phase: StrumPhase,         // WAITING, HEARING, RINGING, DONE
        val strings: List<StrumString>, // per string: verdict, whole cents, sure; empty until the first reading
        val toleranceCents: Float,     // 5 (Relaxed) or 2 (Precise)
    ) : TunerUiState
    data class  IntonationCheck(...) : TunerUiState   // the 12th-fret check (Phase 29): string, step, progress, verdicts
    data class  ChordName(...) : TunerUiState         // the chord name (Phase 30): phase, the settled chord, the last three
}
```

`TunerViewModel` exposes `state: StateFlow<TunerUiState>` plus `mode: StateFlow<TunerMode>`, so the picker chip reacts instantly, and `instrument: StateFlow<Instrument>` for the picker sheet (the tuning in `state` is always one of its presets). Inputs: `onPermissionChanged(granted)`, `onMicRefused`, `setMode`, `setIntonationCheck` (the strum check and the chord name are no tools since 2.0's Phase 74: `heardStrum: StateFlow<HeardStrum>` shows what was heard, [Tuner screen](ui-tuner.md), *The strum check*), `closeToolsOnRequest`, the 12th-fret check's `checkIntonationOf` / `checkIntonationAgain` / `checkNextString`, `setFocusMode`, `setLanguage`, `setInstrument`, `setTuning`, `setLoweredBy`, `deleteCustomTuning`, `toggleString(index)`, `playString(index)`, `stopTone()`, `retry()` (the full shapes are in `TunerUiState.kt` and `TunerViewModel.kt`); `soundingString: StateFlow<Int?>` says which string's reference tone sounds ([Notes, tunings and audio](notes-and-audio.md), *Reference tone*), and `tunedStrings: StateFlow<TunedStrings?>` which strings are ticked off as tuned since the tuner opened, null while the string tick-off (*Tick off tuned strings*, off by default) is off ([Tuner screen](ui-tuner.md), *Strings ticked off*). Picking another instrument switches to its standard tuning, which releases a locked string like any tuning change and, for low strings, the longer window follows on the next frame. Until permission is granted the state is `PermissionRequired` and the pipeline isn't started; the permission status itself lives in the UI (`rememberMicPermissionState`).

`reception` is never composed (`asShown()` sets it to 1); `TunerScreen` passes it, and the exact cents for the meter and the wave, as a `LiveFloat` (NaN without a note) read in layer and draw phases only.

**No first-frame flips.** `MainActivity` has already read the settings, so it passes saved values in as each flow's first value: `TunerScreen(savedMode = …)` (otherwise Guitar showed for ~90 ms before Chromatic), `savedFocusMode` and `savedInstrument` (the button never shows the guitar first). `setMode` switches at once and saves in the background.

## Navigation bar
`:app` `navigation/`, variant **B · Frameless** of the approved mock-up [docs/design/1.x/metronome-nav-preview.html](../design/1.x/metronome-nav-preview.html) (owner decided 2026-10-14). **2.0 (Phase 69):** Tune · Metronome · Practice ("Stemmen · Metronoom · Oefenen"), as 2.0's first mock-up [docs/design/fresh-start-preview.html](../design/fresh-start-preview.html): the metronome, the second most used tool, has a tab of its own again, one tap away, and Practice holds the tools that don't listen (`Destination { TUNER, METRONOME, PRACTICE }`, `destinationsFor`). Settings is no tab: it is set once, so it sits behind the **gear** (below). With the Practice tab's switch off (`ToolSwitches.practiceTab`), or every Practice tool's, the Practice tab is left out and the metronome keeps its own. Nothing else is in the bar: every item is a page that lights up when open. The instrument and tuning are picked with the **instrument button** above the tuner's strings and in the Practice tools ([Tuner screen](ui-tuner.md), *Guitar controls*); the bar's Instrument item, which opened no page and so never lit up, went on 2026-10-19 (owner). The app always opens on the tuner.
- **Look:** no container, frame or edge line that would fight the frameless meter: icons and names straight on the style's background over a **calm field**, a soft wash of the background colour (70 %) that starts 36 dp above the bar and is full from about halfway down, so the screen's last rows and the motifs fade under it. Line icons drawn for Twangle (`NavIcons.kt`, 1.8 dp lines, 2.2 dp on the open tab, small dots filled), redrawn as the owner picked on 2026-11-04 so all three fill the same height and read at 24 dp: Tune a tuner's dial (an arc with the meter's in-tune mark at its top, the needle leaning sharp, its hub); Metronome the case with its base line and a pendulum whose tip swings clear out over the case, the weight inside it; Practice a chord chart as in Chords (a filled nut, three strings, two frets ending at the outer strings, two fingers), which no longer reads as a grid or a "#". Until Phase 69 the Tuner tab's was a tuning fork, and Settings' tab had the gear the gear button now wears. The open tab's icon and name are in the accent (never in-tune green) with the style's own wave mark under the name (`NavMark` in `:core:designsystem`: Ancient a dab with its smudge, Classic an engraved band, Retro a glowing phosphor capsule, Contemporary a voice-memo bar, Futuristic a thin neon bar, Space Age a star); the others in the muted colour. The mark's room is kept under every tab, so nothing moves.
- **Upright** (`AppNavigationBar`): at the bottom, equal tabs, about 74 dp tall above the system's navigation bar (at most 80 dp up to 1.25× text, which the tuner's and metronome's layout tests leave). **On its side** (window wider than tall, `useRail`; `AppNavigationRail`): an 80 dp rail along the start edge, the gear at its top and the tabs one above the other in the middle of the height under it, the field fading out 36 dp past its end edge. The tuner's own layout choice (*Landscape and wide screens*, below) is made in the room the rail leaves. Hidden for Settings and About (they have their back arrow), for the tuning editor (it has its own Cancel / Save) and for focus mode's full-screen tuner (`navigationHidden`, *Landscape and wide screens*), where a tap brings it back with the tuner's controls, so the instrument button and the tabs are one tap away.
- **Insets:** the bar pads itself clear of the gesture bar or buttons (the rail of a side cutout or buttons), and `AppNavigationFrame` marks those insets as used (`consumeWindowInsets`), so the screens' own `safeDrawing` padding doesn't leave the room twice. **Saved state across turning:** `AppNavigationFrame` lays the bar or rail and the screen out with one `Layout` whose screen slot is the same upright and on its side. `rememberSaveable` keys follow the place in the composition, and with a `Row` for the rail and a `Column` for the bar every screen's saved state (the editor's draft and question, panel states) would be lost on turning the phone and come back from the last time in the other orientation on turning back (found on the phone; `NavigationBarTest.turningBetweenBarAndRailKeepsTheContentAndItsSavedState`). The screens keep their quiet or full backgrounds behind it (`StyleBackdrop`, drawn once behind everything).
- **Names:** labelMedium in the style's label face, one line, growing with the font up to 1.3× and set smaller just enough where they don't fit (in 1.1 Dutch "Instellingen" at 2× in a wide face, German "Einstellungen" in the rail; down to 7 sp), the letter spacing relative to the size so a smaller name is set tighter too.
- **The gear** (Phase 69, `SettingsGear`; the first mock-up's "a gear in the corner of every screen is enough", and the tuner mock-up's top row [docs/design/v2-tuner-screens-preview.html](../design/v2-tuner-screens-preview.html): gear top left, the picker chip in the middle from Phase 70, focus mode top right) opens Settings. It is in the **top start corner of every tab**, not only the tuner's, so Settings is one tap from wherever the player is (Claude's pick, asked of the owner on 2026-11-02). Upright the frame hands it to the tab's screen (`AppNavigationFrame`'s content gets `gear`), which puts it at the start of its top row (*One top row*, below): the tuner's, across from focus mode's button, and over the microphone prompt in the same corner; the metronome's `header` slot; the Practice cards' (`PracticeCards(settingsButton)`; the tools a card opens have a back arrow in that corner instead, Phase 69's third step). **On its side** it stands at the top of the rail, the window's top start corner there, and the screens get none, so the tuner's two panes and the other tabs' side layouts are unchanged. Drawn as focus mode's button: the style's button (`StyleButton`) with a 44 dp face, so the two top corners match, the gear icon in 1.8 dp lines; TalkBack hears "Settings", a button (`nav_settings`, the tab's text, so no translation changed). Focus mode's full-screen tuner hides it with the rail. **Settings and About** open over the whole window without the bar or rail, with a back arrow in the top bar (`SettingsScreen(onBack)`); the arrow and Back lead from Settings to the tab whose gear opened it (`Screen.back(settingsOpener)`, the opener kept across turning) and from About to Settings. The widget's tap still shows the tuner from there. Until Phase 69's second step Settings was the bar's fourth tab (tag `nav_settings`, now the gear's, so `:baselineprofile`'s journey finds it unchanged).
- **Practice** (Phase 32; its own tab since Phase 69, `Destination.PRACTICE`, tag `nav_practice`): the practice tools (Chords, Scales, the Capo helper, Ear training and, since Phase 78, the pitch trail), shown as rows under a "Last used" shortcut (big cards until 2026-11-04), each opening its tool under the bar with a back arrow (Phase 69's third step, full screen until 2026-11-03; a tap on the open tab leads back to the cards, and the tab opened from another comes back to the tool it was left on; [Metronome, widget and watch](ui-other-screens.md), *Practice tab*). The tools that listen stay in the tuner (*More tools*, they share its microphone, instrument and strings). "Practice" rather than "Tools": it is short in every language ("Oefenen", "Üben"; "Gereedschap" and "Werkzeuge" would shrink like "Instellingen"). From Phase 32 to 68 the metronome was Practice's first tool and the tab its place, called Practice ([history](history.md)). Three tabs leave each name about 131 dp on the Xiaomi (four, with Settings until the gear, left about 98).
- **TalkBack:** each tab is a `selectable` with `Role.Tab` in a `selectableGroup`, as Material 3's `NavigationBarItem`: "Practice, tab, 3 of 3", "selected" on the open one; the icon says nothing more. A tap on the open tab opens nothing (`onReselect`); on the Tuner tab it closes the tuner's tools ([Tuner screen](ui-tuner.md), *More tools*).
- **Switching tabs** takes the old screen out of the composition: the metronome stops ([Lifecycle](lifecycle.md)), the tuner lets go of the microphone after its 5 s grace. Each tab's saved UI state is kept (`SaveableStateHolder`).
- **Tests:** `NavigationTest` (JVM: tabs and screens, Settings, About and the editor no tabs, the Practice tools on the Practice tab, which comes back to the tool it was left on and whose tap in a tool leads to the cards, Back with Settings to the screen that opened it and from a Practice tool to the cards (Chords opened from the capo helper back to it), a tool whose switch is off showing the cards, bar or rail, the tabs with and without Practice); `NavigationBarTest` (light and dark: tabs heard as tabs by name with the open one selected, upright and on its side; Tune · Metronome · Practice in that order, and without Practice the Metronome tab alone; a tap opens another tab, and on the open one only reselects it; bar at the bottom and at most 80 dp up to 1.25× text, rail at the start, content never under them; Dutch at 2× on a 320 dp phone and on its side every name wholly shown; the open tab's mark in the accent and none under the others; bar and rail hold the tabs and, on its side, the gear, nothing else; the gear at the rail's top above the tabs on its side, handed to the content upright, heard as "Settings", opening Settings, none without a tab; no bar for Settings or the editor); `TunerTabTest` (on the phone: the gear on each tab opens Settings without the bar, and Back or the back arrow returns to that tab); `FocusModeOrientationTest` (on the phone: focus mode turns the app on its side with the compact tuner full screen, no rail and no status bar; a tap brings both back; another tab keeps the side and shows them, and the rail's gear opens Settings still on its side; switched off it turns back upright and lets go, edge to edge with nothing over the status bar; on a large screen it is let go at once, with the lock put on its side meanwhile, and keeps the status bar clear). ## Landscape and wide screens
`tunerLayoutFor(width, height, focusMode, toolPanel)` (`TunerLayout.kt`, JVM-tested) picks the arrangement from the space, not the device: `SINGLE_COLUMN` (max 480 dp wide, drawn bigger on an upright tablet: *Upright tablet* in [Tuner screen](ui-tuner.md)) unless the window is wider than tall; any window wider than tall, however narrow, gets `WIDE`, **the wide layout** (2.0, Phase 73, below), with or without focus mode. The layout never follows the width: focus mode's full-screen tuner hides the rail and the system bars, which changes the width, and with a minimum width (until 2026-10-20) a Galaxy S26 with navigation buttons switched between compact (663 dp without them) and the column (578 dp beside them) about 40 times a second, the screen flickering. The 12th-fret check's panel in the lens's place (`toolPanel`; until Phase 74 the strum check's and the chord name's too, which now show in the plain tuner's places) keeps 1.1's arrangements on its side: `COMPACT` in focus mode, else `TWO_PANE` from 600 dp wide and the column below that. **Focus mode** (owner decided 2026-10-17, Phase 36) has no switch in Settings since 2.0 (Phase 73): one button on the tuner turns it on, and nothing saves it; the app holds it (`AppContainer.focusMode`, a `MutableStateFlow` for the process, so it outlasts the activity turning; a new start opens without it), and `MainActivity` hands it to `TunerScreen(focusMode, onFocusModeChange)`. 1.1's saved switch is read once (`SettingsRepository.takeOldFocusMode()`, at the activity's first creation): it removes the key and, if it was on, the first start of 2.0 opens in focus mode. `TunerScreenTest` checks the wide layout with and without focus mode, the buttons turning it on and off (nothing saved) and the tap for the controls on a phone on its side beside the rail.

**Focus mode turns the whole app** (`FocusTurn` in `:app`'s `FocusMode.kt`, JVM-tested): `MainActivity` sets `requestedOrientation` to `SCREEN_ORIENTATION_SENSOR_LANDSCAPE` while it is on, for every tab, so the screen doesn't turn on each tab switch (only the tuner asking would rotate the activity at every switch). The sensor variant turns the app on its side also with auto-rotate off, and still either way round with the phone. The metronome, Practice and Settings show their own layouts on their side. Switched off, it goes back to `SCREEN_ORIENTATION_UNSPECIFIED` (the manifest sets none), so the screen follows the phone and auto-rotate again. With auto-rotate off, though, Android keeps the screen where it finds the request let go (it locks that rotation: on the Xiaomi the app stayed on its side, `user_rotation` set to 1), so if the window was upright before focus mode turned it, `MainActivity` first asks for `SCREEN_ORIENTATION_PORTRAIT` and lets go once the window is upright (`turningBack`, saved across the recreation on turning). With auto-rotate on the phone decides at once. On a cold start in focus mode the window opens upright and the system turns it, with its own rotation animation. Large screens (Android 16+, at least 600 dp the short way) may ignore the request; there the window's shape decides the layout as before. **Large screens are let go at once** when focus mode goes off, never asked for upright (`largeScreen`, at least 600 dp the short way; Phase 52): the Lenovo Tab M11 (Android 15, ZUI 17, `ignoreOrientationRequest` on) turns on its side for `SENSOR_LANDSCAPE`, but answers `PORTRAIT` with a letterbox (an upright window in the middle of the screen still on its side) wherever its rotation lock is on its side, and once that letterbox ended a grey band lay behind the status bar on every tab (the app's content pushed below it) until the tablet turned. Let go, the tablet goes back to its rotation lock, which it keeps where the user left it (upright when it was held upright, measured 2026-10-27). **UI Automator moves the lock:** each `uiautomator dump` (and a test's `UiDevice.freezeRotation`) locks the rotation where the screen is at that moment (`UiAutomationConnection#restoreRotationStateLocked` in `dumpsys window`, *RotationLockHistory*), so a check that reads the screen with it while focus mode holds the tablet on its side leaves the lock there, and the tablet stays on its side after focus mode, as Android is told. Check focus mode's way back with plain `adb shell input tap` at known places.

**Full screen** (Phase 40, owner 2026-10-19: "focus mode should be all about displaying the meter as big as possible"; the rough mock-up [docs/design/1.x/focus-mode-preview.html](../design/1.x/focus-mode-preview.html)): while focus mode's tuner shows without its controls, `TunerContent` says so (`onFullScreenChange`, through `TunerScreen`), and `MainActivity` hides the rail (`AppNavigationFrame(navigationHidden)`) and the status and navigation bars (`WindowInsetsControllerCompat`, a swipe from the edge shows them for a moment). The controls shown (a tap, an open panel), another tab, or focus mode off bring both back. Only the tuner goes full screen: the other tabs keep their side layouts with the rail, and the whole app stays on its side, so the screen doesn't turn on a tab switch.

**The wide layout** (`WideLayout` in `TunerLayouts.kt`, 2.0 Phase 73; the tuner mock-up's "On its side", [docs/design/v2-tuner-screens-preview.html](../design/v2-tuner-screens-preview.html); v2-plan.md, *The lens*, Size wide): any window wider than tall, the same screen laid out wide.
- **With its controls** (a phone or tablet on its side, the rail beside it): the top row (on a phone the picker chip in the middle, where the tablet and the upright tuner have "Tune" with the chip on its own line under it, Phase 77, [Tuner screen](ui-tuner.md), *Picker chip*; focus mode's button at its end, its outline 16 dp from the side and its touch area 8 dp from the top, as upright; the gear is at the rail's top), the ruler across the full width under it, showing more of the scale than upright, the lens wide under that (the window less 24 dp each side, as high as the rest leave, at most half its width: `Lens(wide)`), and one line under the lens, 12 dp below it (`WideBottomLine`): the word at its start (`TuneWordLine(start = true)`, set a little smaller, its two lines at the start) and the pegs in the middle (`WidePegs`: 24 dp kept above them for a strum's marks; until 2026-11-03 a 48 dp slot each side held the 12th-fret check's button before the first string, and before Phase 74 the strum check's switch or the "more tools" button after the last; the pegs 56 dp apart, `WIDE_PEG_PITCH`, as the upright six-string row spreads them: an 8-string row there has room and is not squeezed). On a phone on its side the lens is about 5 : 1 here.

- **Large fonts:** the lens gives way in height down to 72 dp (`WIDE_LENS_LEAST`), then the whole scrolls; the word sets itself smaller to keep its line.
- Each of the three looks draws wide (`LocalLensWide`, Phase 72): the Light arc's ±0.8 rad fan fitted to the box, the strobe's bands across it, the trail's falling seconds in the short box. `WideLayoutTest` checks the layout on phones and a tablet on their side, with and without focus mode (the ruler across, the lens 24 dp in, the word under it at the start, the pegs centred or at the end, the chip on top, no pegs and no chip in focus mode until a tap) and each look drawn in the wide box, light and dark.

**Focus mode's full-screen tuner** (`CompactLayout`, around the wide layout without its controls, or the 12th-fret check's panel):
- **With the 12th-fret check on** (until Phase 74 the strum check and the chord name too): the tool's panel in the lens's place beside its own text and buttons (`CompactRow`), as before full screen. The note column is measured first and the panel takes all the width left (`FitGauge`, at most 840 dp, keeping 2:1). The note column never takes the panel's last 160 dp (its smallest width) and its lines wrap instead: at 2× text in Space Age's wide face the 12th-fret check's Dutch lines took the whole row and left its panel no width (overnight run, 2026-10-17). In the strum check the note column leaves the panel at least 48 dp a string (its columns are buttons), so its lines wrap sooner (Futuristic and Space Age beside the rail had 35 dp columns, overnight run 2026-10-18). The 12th-fret check shows a small string row under its text (32 dp chips, not buttons, hidden from TalkBack).
- The picker chip and the pegs (with a strum's marks) are hidden; the count or a chord's words still take the word's place, a chord's name the ruler's.
- **Tap for the controls:** a tap anywhere, or TalkBack's "Show controls" button, cross-fades to the same layout with its controls (the wide layout with the chip and the pegs; with a tool on the two panes where 600 dp fit, else the column) and the rail and the system bars for 5 s (`COMPACT_CONTROLS_SHOWN_MS`), lengthened by Android's "time to take action" setting. Every touch restarts the time, and an open instrument and tuning panel holds it. Local UI state; a rotation starts full screen again.
- **The focus mode button** (2.0, Phase 73: one button, no switch in Settings; `FocusModeButton`, no word, the Material Symbols icons; the app's `StyleButton`, the same 44 dp face as the gear across from it, after a bare icon in the top corner was hardly visible, owner 2026-10-19): with focus mode off, "full screen" (four corners pointing out; TalkBack "Focus mode") turns it on, at the end of the picker chip's row: the top end corner, upright and on its side, in the same place in both modes (owner, 2026-10-25, idea A1 of the Phase 43 rough mock-up), its outline 16 dp from the side. (Owner, 2026-10-19: before, the exit button was only among the controls, which look as if a tap had left focus mode, so people tapped it to get back to the big meter and switched focus mode off instead; the corner button replaced the "Tap to show the controls" hint, see [history.md](history.md).) Upright in focus mode (a large screen keeping its rotation lock) it is the exit button. Back in focus mode switches it off too before it leaves the app, as Back leaves a video player's full screen (`BackHandler`). All of them call `onFocusModeChange`, which sets the app's `focusMode`, so the app turns as described above. With the system bars hidden, the first swipe from the edge may only show them, so the button is the main way out.
- `CompactLandscapeStylesTest` checks focus mode on a phone and a tablet on their side, full screen (the lens covers its box, clearly drawn, and TalkBack skips it; the ruler across the top, the lens wide under it and the word at the start under it, the string small at the line's end in guitar mode and none in Any note, nothing else of the tuner, the word and a tip wholly shown at 2× font, drawn in light and dark, the exit button wholly shown in the top end corner over the ruler's end, also at 2× font, "Show controls" works). Layout runs in the light theme only. `TunerContentTest` checks the layout, that it reports full screen only while the controls are away, the exit button and its twin sharing the corner (upright too), that the controls' button goes back to full screen without leaving focus mode, and that the focus mode button stands at the end of the chip's row, in the same place in both modes, with the chip centred beside it and wholly shown in Dutch and Russian at 2× text on a 360 dp phone.

**Two-pane layout** (`TwoPaneLayout`; since 2.0's Phase 73 only for the 12th-fret check's panel on its side, also while focus mode's controls are up with it on):
- **Readout pane** (start): the ruler across the pane (since 2.0's Phase 71 on a phone too), then `GaugeAboveStatus`, which measures the word (or a tool's lines) first and shrinks the lens (2:1, 160–560 dp wide) so all fit a phone on its side (~330 dp tall), 24 dp left above and below for the lens's glow.
- **Controls pane** (end): picker chip and the strings, max 480 dp, with 56 dp clearance top and bottom: a margin when the column scrolls (very large fonts). Without it the controls would sit higher wherever the column only just scrolls.
- Each pane scrolls on its own with very large fonts; both screens use `WindowInsets.safeDrawing` (the camera cutout is at the side in landscape).
- The activity is recreated on rotation (no `configChanges`); mode and tuning are saved, the locked string lives in the ViewModel, and the 5 s grace keeps the `AudioRecord` session.

## Accessibility
- **TalkBack:** the word under the lens (`TuneWordLine`; `NoteDisplay` until 2.0's Phase 71) speaks through one node whose description is the reading in words ("E 2, 12 cents flat, tune up", "F sharp 2, in tune", "Play a string"), a *polite live region*; its visible texts are `hideFromAccessibility()`. That node is a layer of its own under the block (`matchParentSize`), not the block itself, so nothing inside the block is part of the live region (the signal bars sat in the pill until 2026-10-20 and changed their words with the sound, which could make TalkBack read the reading again early). `SpokenReadingThrottle` (pure, `:core:dsp` `speech/` since Phase 65, shared with the watch) decides what TalkBack gets from ~47 updates a second: the first text at once, a new note or in-tune change after 400 ms, losing the note after 1.5 s, cents-only changes of a reading never (Phase 81; other paced texts, Listen's tempo and the tuner's waiting line, at most every 2 s). `PacedSpeech` (`rememberPacedSpeech`, `pacedSpeech`) holds a throttle and the text given; `TunerContent` keeps one for the whole screen and hands it to each word line, because the word is built afresh when the state switches between a note and listening, and a throttle inside it started over each time, so every pluck and every "Play a string" was said at once. Listen's tempo on the metronome is paced the same way. The meter is hidden (`clearAndSetSemantics {}`). Phase 65: the pacing's key is the note and its side, flat, sharp or in tune (`spokenReadingKey`, through `:core:dsp`'s `SpokenSide`, which the watch's key uses too), so turning a string past the note is said after 400 ms like a new note, not up to 2 s late as a cents-only change; and "Play a string" coming back as a pluck dies away, the same words as the last time no note was heard, is published but not announced (`SpokenReadingThrottle.announced`, `PacedSpeech.announced`: the layer drops its live region for it), so TalkBack reads it when touched instead of talking over the next pluck; other words with no note (a tip, a locked string's hint) are said as before. **Phase 81, a reading said once:** with TalkBack's voice in the room the tuner once heard its own spoken reading ("12 cents flat") as a note, which changed the cents, which TalkBack said again: a loop (the owner's check, 2026-11-06). The microphone's frames are now set aside while TalkBack speaks (`ScreenReaderSpeech`, [Signal pipeline](signal-pipeline.md)), and a reading is said once per situation: its key is a `SpokenReadingKey` (`:core:dsp`), the note, the side the word on screen says (Tighten or Too low → flat, Loosen or Too high → sharp, In tune; none before the word settles) and the tip or the trail's motion said with it (`spokenReadingKey(readout, word, tip, motion)`). A situation is said once it has lasted 400 ms, with the cents it has then; while it lasts, the throttle keeps the text TalkBack was given, cents included, so the live region's description doesn't change and TalkBack has nothing to say again (`SpokenReadingThrottleTest`, `SpokenReadingKeyTest`, `TunerContentTest.theSpokenReadingDoesNotChangeOnItsOwn`). The key takes the side from the word rather than the cents' sign because the word is already held steady near the note (`TuningCue`'s margins, `SteadyHint`): until Phase 81 the side came from the rounded cents, so a reading wobbling across the note (−1, 0, +1) was three situations, each said. The cost: a player turning a flat string up hears "12 cents flat, Tighten" once and then "in tune", not the cents on the way (touching the reading repeats what was said); the watch's "calmly" rule, now the phone's too. With nothing played, the waiting line and a tip that comes and goes with the room's sounds ("Play a bit louder", which a soft sound in the room brings up, TalkBack on or off) were each announced as they flipped, every few seconds on the Xiaomi, and TalkBack speaking the tip cleared it (the frames set aside, a fresh interpreter after), which brought "Play a string" back to be said: a no-note text that is one of the last two said with no note is now published but not announced, the Phase 65 rule widened (`SpokenReadingThrottleTest`, *a tip flipping with the waiting line is said once*); a text the player brings (a locked string's hint) is still said.
- **TalkBack's own voice is no note** (Phase 81): with TalkBack on and the speaker loud, the microphone hears TalkBack saying the reading. Everything that listens sets its frames aside while a screen reader's voice plays and 0.4 s after: the tuner and its tools, the pitch trail, the metronome's Listen, Chords' Listen, Ear training's Play it back and the watch's tuner.
