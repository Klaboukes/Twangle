## Owner checks (live tests)
Done by the owner by hand, with a real guitar or headset. They are not roadmap increments: `/roadmap-step` skips them.

- ☐ **A string change over a ringing string** (Phase 89, 2026-11-10; any time, a guitar in standard tuning, guitar mode): pluck the low E hard and let it ring; a second later pluck the high E softly without muting the low E: the needle should move to the high E within about a quarter second. Then the same for low E → B and A → high E. If the needle stays on the low string while the new one rings, say how hard you plucked it: that is the detector hearing both strings as the lower one (a known limit), not the hold this fixed. Also once with a TV on: a single string left ringing out must still read as itself and then go blank, never jump to another string
- ☐ **When you have the gear** (postponed 2026-10-16, no hurry):
  - Phase 5, a Bluetooth headset: with one connected, the tuner still listens through the phone's mic and reads a string correctly
  - Wired earbuds with a mic (3.5 mm plug, or USB-C), for a noisy room (2026-10-31): with them plugged in, Android listens through the earbud mic, which Twangle allows (only a Bluetooth headset is overruled), so the mic can lie close to the guitar. Lay the mic on the guitar's top a few centimetres from the soundhole (not in it), hands off the cable, and tune all six strings, first in a quiet room, then with loud music from the laptop: the note and cents follow each string, the low E included, at least as quickly and steadily as with the phone's own mic, and better in the noise; the reference tone plays in the earbuds; pulling the plug goes back to the phone's mic without a restart. If it passes, one line on the website's help page in English and Dutch ("Noisy room? Plug in wired earbuds and lay the mic on the guitar"), no hint in the app; if the low strings fail, the line names guitar and ukulele only
  - Phase 15, a bass (or a 7-string guitar or cello): the lowest strings read correctly (B0, E1, B1, C2), and the tuner shows no note while the amp only hums

## Phase 91 — What the second code review found
Goal: everything the second code review of 2026-11-10 found, after Phases 89 and 90 had fixed the first review's list (all 20 items held but two of the full check's; `test lint assembleDebug` passed on 5472dc08), including the first review's "not planned" leftovers, so nothing found is left lying about. Fixes inside existing tools need no switch of their own; each comes with a test that fails without it, and what a player can see or hear gets the usual phone check. The two full-check holes go first: each could let an untested build reach a release.

Tooling first:
- ☑ **A full check whose build fails isn't recorded as passed:** when the one build fails, no lane runs, so `phones_failed` and `unrun` stay 0 and the record gets `phones 0` (`scripts/full-check.sh`, the record lines near its end), which `scripts/release.sh bundle` accepts, though the run itself exits 1. The record counts a failed build (and a build cut off by `BUILD_TIMEOUT`) as a failure. A test of the record's logic, or a `--dry-run` case that shows it. Done 2026-11-10: a failed or cut-off build writes `phones 1 ... failed build` (a failed line names what failed: build, no-device, release, sweep, contrast, languages), `scripts/release.sh full-check` says it; `scripts/full-check.sh --self-check` runs 11 made-up cases (4 wrong on the old logic), and a real run with `BUILD_TIMEOUT=3` recorded `phones 1 ... failed build` and exited 1
- ☑ **`--fixed` vouches only for a real re-check:** a module that fails keeps its older pass note (`ui-tests.sh` writes notes, never removes one), and that note may come from a quick day run without the `@Thorough` tests, the high contrast or the languages, so right after a failed full check `--since-pass` says "nothing to run" and `--fixed` records a pass with nothing re-checked. A module's pass note goes when it fails; `--fixed` asks for every failed module's note to be newer than the failed run and from a thorough run, and refuses when what failed was the build, the release smoke test, the high contrast, a language check or no device at all (those need the full check again). Done 2026-11-10: a pass note now holds its time and `thorough` or `quick`, and a module whose tests fail from a clean tree loses it; a failed phones line names the modules whose sweep failed (`modules :feature:tuner,:app`); `--fixed` refuses anything but sweeps, a failed module not passed again `--thorough` after the run, or any module re-checked quick since; `--self-check` has 17 `--fixed` cases, and a real try on the Xiaomi with a scratch notes folder (`UI_TESTS_PASSED`): a cut-off run removed `:core:testing`'s note, a quick pass was refused, a `--thorough` one accepted
- ☐ **Store screenshots change the device's settings only under the lock:** `scripts/store-screenshots.sh` reads the font size and the app's languages before `ui-tests.sh` takes the lock and puts them back in its exit trap after the lock is gone, also when `ui-tests.sh` exits 5 because another run has the device, so it can write under a live run and keep a test's 100 % as the tablet's own size (the owner's is 130 %). Read and put back only while holding the lock; nothing put back after an exit 5
- ☐ **The Baseline Profile made under the phone's lock:** `./gradlew :app:generateBaselineProfile` (CLAUDE.md's *Commands*, the release skill) uninstalls the app by hand with no lock and no device picked, so it stops another session's UI test run, and fails with "more than one device" when the watch is connected. The app:
- ☐ **Octave strings in other tunings stay guarded:** Phase 89's string-change rule lets a jump onto another string pass with a 7 dB rise instead of 10, and in Drop D, Open G, Open D, DADGAD, Open C and Open E two strings are exactly an octave apart, so re-plucking a ringing low D a little harder can now flip the needle to the D an octave up (YIN's most common slip on a low string); every test uses standard tuning. Tests re-plucking over a ringing string in Drop D and Open G; if they fail, the 10 dB rule stays for a jump of exactly an octave, the 7 dB one for two octaves and a twelfth. With it: the jump restarts only on a frame that is itself on the new string (today a stray non-string frame can complete it); the 7 dB margin over a TV's talk (6 dB in one recording) backed by more room recordings or asked of two frames; and the watch gets the rule too (`WatchPitchPipeline` doesn't give its smoother the tuning's strings). The owner check *A string change over a ringing string* gains an Open G round

  - the one-time focus-mode move on 2.0's first start (`takeOldFocusMode`) runs through `container.save {}` like every other write
  - a tuner mode pick whose save failed (phone full) no longer flips back at the next settings change
  - `PitchSmoother.weightOf` gives a NaN confidence the lowest weight instead of blanking the needle for a frame
