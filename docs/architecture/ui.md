## UI state model
```kotlin
enum class TunerMode { AUTO, CHROMATIC }   // in :core:settings, saved by name

sealed interface TunerUiState {
    data object PermissionRequired : TunerUiState
    data class  Error(val reason: TunerError) : TunerUiState
    data class  Listening(val mode: TunerMode, val tuning: Tuning, val a4Hz: Float, val lockedString: Int?, val notation: Notation) : TunerUiState   // no usable signal
    data class  Detected(
        val mode: TunerMode,
        val tuning: Tuning,
        val a4Hz: Float,               // concert pitch in use (A4 calibration)
        val notation: Notation,        // how note names are written
        val noteName: String,          // target note in that notation, e.g. "E", "D♭", "Re"
        val octave: Int,               // e.g. 2
        val frequencyHz: Float,        // smoothed
        val cents: Float,              // smoothed; Auto: unwrapped distance to the string, Chromatic: about ±65
        val targetString: Int?,        // index into tuning, Auto mode only
        val lockedString: Int?,        // string the user locked (then also targetString), else null
        val inTune: Boolean,           // ≤ 5 cents for ≥ 300 ms, released past 7 (Precise: ≤ 2, past 3)
        val hint: TunerHint?,          // the steady hint line: in tune, tune up or tune down
        val reception: Float,          // 0..1 how well the note is heard (ReceptionTracker), drawn not written
        val tip: ReceptionTip?,        // too soft / too noisy / too loud, held steady (Listening has it too)
    ) : TunerUiState
    data class  StrumCheck(            // strum check on, guitar mode (see Strum check view)
        val tuning: Tuning,
        val notation: Notation,
        val phase: StrumPhase,         // WAITING, HEARING, RINGING, DONE
        val strings: List<StrumString>, // per string: verdict, whole cents, sure; empty until the first reading
        val toleranceCents: Float,     // 5 (Relaxed) or 2 (Precise)
    ) : TunerUiState
}
```

`TunerViewModel` exposes `state: StateFlow<TunerUiState>` plus `mode: StateFlow<TunerMode>`, so the mode switch reacts instantly, and `instrument: StateFlow<Instrument>` for the instrument and tuning panel (the tuning in `state` is always one of its presets). Inputs: `onPermissionChanged(granted)`, `setMode`, `setStrumCheck(on)` (with `strumCheck: StateFlow<Boolean>`), `setInstrument`, `setTuning`, `setStyle`, `toggleString(index)`, `playString(index)`, `stopTone()`, `retry()`; `soundingString: StateFlow<Int?>` says which string's reference tone sounds ([Notes, tunings and audio](notes-and-audio.md), *Reference tone*). Picking another instrument switches to its standard tuning, which releases a locked string like any tuning change and, for low strings, the longer window follows on the next frame. Until permission is granted the state is `PermissionRequired` and the pipeline isn't started; the permission status itself lives in the UI (`rememberMicPermissionState`).

`reception` is never composed (`asShown()` sets it to 1); `TunerScreen` passes it as a lambda read in layer and draw phases only.

**No first-frame flips.** `MainActivity` has already read the settings, so it passes saved values in as each flow's first value: `TunerScreen(savedMode = …)` (otherwise Guitar showed for ~90 ms before Chromatic), `savedFocusMode` and `savedInstrument` (the button never shows the guitar first). `setMode` switches at once and saves in the background.

## Navigation bar
`:app` `navigation/`, variant **B · Frameless** of the approved mock-up [docs/design/metronome-nav-preview.html](../design/metronome-nav-preview.html) (owner decided 2026-10-14). Three tabs, Tuner · Metronome · Settings ("Stemmer · Metronoom · Instellingen"), and a fourth item between Tuner and Metronome, **Instrument** (also "Instrument" in Dutch), which is no tab (below); the app always opens on the tuner.
- **Look:** no container, frame or edge line that would fight the frameless meter: icons and names straight on the style's background over a **calm field**, a soft wash of the background colour (70 %) that starts 36 dp above the bar and is full from about halfway down, so the screen's last rows and the motifs fade under it. Line icons drawn for Twangle (tuning fork, metronome, gear; `NavIcons.kt`, 1.8 dp lines, 2.2 dp on the open tab). The open tab's icon and name are in the accent (never in-tune green) with the style's own wave mark under the name (`NavMark` in `:core:designsystem`: Ancient a dab with its smudge, Classic an engraved band, Retro a glowing phosphor capsule, Contemporary a voice-memo bar, Futuristic a thin neon bar, Space Age a star); the others in the muted colour. The mark's room is kept under every tab, so nothing moves.
- **Instrument item** (`InstrumentItem`, owner's request 2026-10-15; the label fixed rather than the instrument's name): a guitar headstock with three pegs a side (`INSTRUMENT_ICON`, drawn like the other icons) over "Instrument" (the same in Dutch; not "Tuning", because "Tuner" and "Tuning" look alike, and in most languages share one root: Stemmer / Stemming, Stimmgerät / Stimmung, Afinador / Afinación), always in the muted colour and never with the mark, since it opens no screen. A tap shows the tuner (from any tab) with the instrument and tuning panel open over it (`MainActivity`'s `tuningPanelOpen`, saved, so a turned phone keeps it open), so a tuning can be tried on the strings at once. Without the microphone it works too: the panel opens over the permission prompt, and the tuning picked is the one the tuner listens for once allowed. Opening it was chosen over a disabled item, which would only puzzle the player. TalkBack: "Instrument, Guitar, Standard, button, double-tap to change instrument or tuning" (`Role.Button`, the picked instrument and tuning as its state, a custom tuning by its own name).
- **Upright** (`AppNavigationBar`): at the bottom, three equal tabs and the Instrument item, about 74 dp tall above the system's navigation bar (at most 80 dp up to 1.25× text, which the tuner's and metronome's layout tests leave). **On its side** (window wider than tall, `useRail`; `AppNavigationRail`): an 80 dp rail along the start edge, the tabs and the Instrument item one above the other in the middle, the field fading out 36 dp past its end edge. The tuner's own layout choice (*Landscape and wide screens*, below) is made in the room the rail leaves. Hidden for the tuning editor (it has its own Cancel / Save) and for focus mode's full-screen tuner (`navigationHidden`, *Landscape and wide screens*), where a tap brings it back with the tuner's controls, so the Instrument item and the tabs are one tap away.
- **Insets:** the bar pads itself clear of the gesture bar or buttons (the rail of a side cutout or buttons), and `AppNavigationFrame` marks those insets as used (`consumeWindowInsets`), so the screens' own `safeDrawing` padding doesn't leave the room twice. **Saved state across turning:** `AppNavigationFrame` lays the bar or rail and the screen out with one `Layout` whose screen slot is the same upright and on its side. `rememberSaveable` keys follow the place in the composition, and with a `Row` for the rail and a `Column` for the bar every screen's saved state (the editor's draft and question, panel states) would be lost on turning the phone and come back from the last time in the other orientation on turning back (found on the phone; `NavigationBarTest.turningBetweenBarAndRailKeepsTheContentAndItsSavedState`). The screens keep their quiet or full backgrounds behind it (`StyleBackdrop`, drawn once behind everything).
- **Names:** labelMedium in the style's label face, one line, growing with the font up to 1.3× and set smaller just enough where they don't fit (Dutch "Instellingen" at 2× in a wide face, German "Einstellungen" in the rail; down to 7 sp), the letter spacing relative to the size so a smaller name is set tighter too.
- **Practice** (Phase 32): with the Practice tab's switch on (every build since Phase 34, `AppNavigationFrame(practice = true)`) the Metronome tab is called Practice ("Oefenen"), with the same metronome icon, since the metronome is still what it holds first, and the tour's last step says "Practice and settings" (`tourTextOf(practice)`). Its `Destination` and tag stay `METRONOME` / `nav_metronome`, so the Baseline Profile generator and the tests find it either way. Why this shape (owner agreed, 2026-10-16): the bar keeps four items, since five would leave each name about 78 dp on the Xiaomi instead of about 98, too little for long words in 16 languages at 2× text (Dutch "Instellingen" already shrinks with four). The tools that listen stay in the tuner (*More tools*, they share its microphone, instrument and strings); the ones that don't listen (Metronome, Chords, the Capo helper, and later ones such as ear training, a drone or a practice timer) go into Practice, so the bar doesn't change again. "Practice" rather than "Tools": it is short in every language ("Oefenen", "Üben"; "Gereedschap" and "Werkzeuge" would shrink like "Instellingen").
- **TalkBack:** each tab is a `selectable` with `Role.Tab` in a `selectableGroup`, as Material 3's `NavigationBarItem`: "Settings, tab, 3 of 3", "selected" on the open one; the icon says nothing more. A tap on the open tab opens nothing (`onReselect`); on the Tuner tab it closes the tuner's tools ([Tuner screen](ui-tuner.md), *More tools*).
- **Switching tabs** takes the old screen out of the composition: the metronome stops ([Lifecycle](lifecycle.md)), the tuner lets go of the microphone after its 5 s grace. Each tab's saved UI state is kept (`SaveableStateHolder`).
- **Tests:** `NavigationTest` (JVM: tabs and screens, Back, bar or rail); `NavigationBarTest` (every style, light and dark: tabs heard as tabs by name with the open one selected, upright and on its side; a tap opens another tab, and on the open one only reselects it; bar at the bottom and at most 80 dp up to 1.25× text, rail at the start, content never under them; Dutch at 2× on a 320 dp phone and on its side every name wholly shown; the open tab's mark in the accent and none under the others; the Instrument item a button after the Tuner tab, heard with its state, never selected nor in the accent, wholly shown in Dutch at 2×; no bar for the editor); `FocusModeOrientationTest` (on the phone: focus mode turns the app on its side with the compact tuner full screen, no rail and no status bar; a tap brings both back; another tab keeps the side and shows them; switched off it turns back upright and lets go). The tags `nav_tuner`, `nav_instrument`, `nav_metronome`, `nav_settings` (`NavigationTestTags`) are resource ids for UI Automator (`testTagsAsResourceId` on `MainActivity`'s root), used by `:baselineprofile`.

## Landscape and wide screens
`tunerLayoutFor(width, height, compactLandscape)` (`TunerLayout.kt`, JVM-tested) picks the arrangement from the space, not the device: `SINGLE_COLUMN` (max 480 dp wide) unless the window is at least 600 dp wide *and* wider than tall. Then `TWO_PANE` by default, or `COMPACT` in **focus mode** (the setting "Focus mode", `focusMode`, off by default; owner decided 2026-10-17, Phase 36), so a phone turned on its side by accident keeps the full layout. `TunerScreen` passes `compactLandscape = focusMode`. `TunerScreenTest` checks both layouts, a live change and the tap for the controls on a phone on its side beside the rail.

**Focus mode turns the whole app** (`FocusTurn` in `:app`'s `FocusMode.kt`, JVM-tested): `MainActivity` sets `requestedOrientation` to `SCREEN_ORIENTATION_SENSOR_LANDSCAPE` while it is on, for every tab, so the screen doesn't turn on each tab switch (only the tuner asking would rotate the activity at every switch). The sensor variant turns the app on its side also with auto-rotate off, and still either way round with the phone. The metronome, Practice and Settings show their own layouts on their side. Switched off, it goes back to `SCREEN_ORIENTATION_UNSPECIFIED` (the manifest sets none), so the screen follows the phone and auto-rotate again. With auto-rotate off, though, Android keeps the screen where it finds the request let go (it locks that rotation: on the Xiaomi the app stayed on its side, `user_rotation` set to 1), so if the window was upright before focus mode turned it, `MainActivity` first asks for `SCREEN_ORIENTATION_PORTRAIT` and lets go once the window is upright (`turningBack`, saved across the recreation on turning). With auto-rotate on the phone decides at once. On a cold start in focus mode the window opens upright and the system turns it, with its own rotation animation. Large screens (Android 16+, at least 600 dp the short way) may ignore the request; there the window's shape decides the layout as before.

**Full screen** (Phase 40, owner 2026-10-19: "focus mode should be all about displaying the meter as big as possible"; the rough mock-up [docs/design/focus-mode-preview.html](../design/focus-mode-preview.html)): while the compact layout shows without its controls, `TunerContent` says so (`onFullScreenChange`, through `TunerScreen`), and `MainActivity` hides the rail (`AppNavigationFrame(navigationHidden)`) and the status and navigation bars (`WindowInsetsControllerCompat`, a swipe from the edge shows them for a moment). The controls shown (a tap, an open panel, the tour), another tab, or focus mode off bring both back. Only the tuner goes full screen: the other tabs keep their side layouts with the rail, and the whole app stays on its side, so the screen doesn't turn on a tab switch.

**Compact layout** (`CompactLayout`): only what matters while tuning, big enough to read from a distance.
- **The plain tuner** (`FocusMeter`): the meter over the whole screen, keeping its 2:1 shape, 8 dp from the edges (`FOCUS_METER_MARGIN`, at most 1200 dp wide): on a phone on its side its height decides, about 750 × 375 dp on the Xiaomi 12X, against about 490 dp wide beside the rail and the note column before. The note (`FocusNote` in `NoteDisplay.kt`) is small in the top start corner, where every meter look leaves room above its scale: the name at 48 dp (under half the big note) and the octave, turning the "in tune" colour in tune; without a note the hint ("Play a string", "Play the D3 string") in its place; a reception tip in a line under it; at most 240 dp wide, so long lines wrap. Nothing else: no cents, frequency, string row, wave or signal bars, since the meter shows how far off the note is (the wave view shows again with the controls). TalkBack hears it as the big note (one polite live region).
- **With a tool on** (strum check, 12th-fret check, chord name, pitch trail): the tool's panel in the meter's place beside its own text and buttons, as before full screen. The note column is measured first and the panel takes all the width left (`FitGauge`, at most 840 dp, keeping 2:1). The note column never takes the panel's last 160 dp (its smallest width) and its lines wrap instead: at 2× text in Space Age's wide face the 12th-fret check's Dutch lines took the whole row and left its panel no width (overnight run, 2026-10-17). In the strum check the note column leaves the panel at least 48 dp a string (its columns are buttons), so its lines wrap sooner (Futuristic and Space Age beside the rail had 35 dp columns, overnight run 2026-10-18). The 12th-fret check shows a small string row under its text (32 dp chips, not buttons, hidden from TalkBack).
- Mode switch, strum check switch, string buttons and more tools are hidden.
- **Tap for the controls:** a tap anywhere, or TalkBack's "Show controls" button, cross-fades to the two-pane layout for 5 s (`COMPACT_CONTROLS_SHOWN_MS`), lengthened by Android's "time to take action" setting. Every touch restarts the time, and an open instrument and tuning panel holds it. Local UI state; a rotation starts compact again.
- **Leaving focus mode** (owner, 2026-10-19: no trip to Settings): the controls a tap brings up have an exit button in their top end corner (`ExitFocusButton`, the Material Symbols "fullscreen_exit" icon, four corners pointing in, no word; TalkBack "Exit focus mode"), never over the full-screen meter itself, which stays clean. And Back in focus mode switches it off before it leaves the app, as Back leaves a video player's full screen (`BackHandler`, not while the tour runs, where Back ends the tour). Both call `TunerViewModel.exitFocusMode`, which does what the Settings switch does, so the app turns back upright as described above. With the system bars hidden, the first swipe from the edge may only show them, so the button is the main way out.
- **The hint:** when the compact layout appears, a quiet "Tap to show the controls" (body text in `onSurfaceVariant`, one line) sits over the layout, so nothing moves: in the top end corner beside the full-screen meter (the note has the other one), at the bottom centre with a tool on; for 4 s (`COMPACT_TAP_HINT_SHOWN_MS`, lengthened by "time to take action"), then fades out (400 ms); a tap ends it at once. It shows a fixed time, never in and out with the sound, and TalkBack skips it (the screen is already its "Show controls" button).
- `CompactLandscapeStylesTest` checks every style and meter look on a phone and a tablet on their side, full screen (the meter fills the screen with the note in its corner and nothing else of the tuner, the note and a tip wholly shown at 2× font, drawn in light and dark, the hint in the top end corner, "Show controls" works). Layout runs in the light theme only: a style's fonts and shapes don't change with dark. `TunerContentTest` checks the layout in one style, and that it reports full screen only while the controls are away.

**Two-pane layout** (`TwoPaneLayout`, also shown while the compact layout's controls are up):
- **Readout pane** (start): `GaugeAboveNote` measures the note first and shrinks the meter (2:1, 160–560 dp wide) so both fit a phone on its side (~330 dp tall).
- **Controls pane** (end): mode switch, strum check switch and strings, max 480 dp, with 56 dp clearance top and bottom: a margin when the column scrolls (very large fonts). Without it the controls would sit higher wherever the column only just scrolls.
- Each pane scrolls on its own with very large fonts; both screens use `WindowInsets.safeDrawing` (the camera cutout is at the side in landscape).
- The activity is recreated on rotation (no `configChanges`); mode and tuning are saved, the locked string lives in the ViewModel, and the 5 s grace keeps the `AudioRecord` session.
- **Settings** scrolls the full width but keeps its rows in a centred column at most 600 dp wide.
- **Right to left** (Arabic): both layouts mirror with the language, so the readout pane, the compact layout's note column and the rail sit on the right and the meter on the left; the meter, the string row and the other measuring graphics inside them stay left to right (see Languages).

## Accessibility
- **TalkBack:** `NoteDisplay` speaks through one node whose description is the reading in words ("E 2, 12 cents flat, tune up", "F sharp 2, in tune", "Play a string"), a *polite live region*; its visible texts are `hideFromAccessibility()`. That node is a layer of its own under the block (`matchParentSize`), not the block itself, so the signal bars' button, which sits in the pill and changes its words with the sound, is not inside the live region and can't make TalkBack read the reading again early; drawn on top, the button is still found by touch. `SpokenReadingThrottle` (pure, `:core:designsystem`) decides what TalkBack gets from ~47 updates a second: the first text at once, a new note or in-tune change after 400 ms, losing the note after 1.5 s, cents-only changes at most every 2 s. `PacedSpeech` (`rememberPacedSpeech`, `pacedSpeech`) holds a throttle and the text given; `TunerContent` keeps one for the whole screen and hands it to each `NoteDisplay`, because the note's display is built afresh when the state switches between a note and listening, and a throttle inside it started over each time, so every pluck and every "Play a string" was said at once. Listen's tempo on the metronome is paced the same way. The meter and wave are hidden (`clearAndSetSemantics {}`).
- **Separators:** where code joins spoken parts (the panel's open strings, the strum check's "12 cents flat, tune up"), the separator is `tuner_spoken_separator`: ", " in most languages, the Arabic comma "، " in Arabic, "、" in Japanese, "，" in Chinese, the same marks the languages' spoken format strings use.
- **Spoken note names:** every TalkBack text naming a note goes through `NoteNameSpeech` (`:core:designsystem`, `rememberNoteNameSpeech()`, tested against every name the app can show): readout, string chips, locked-string hint, the panel's tunings and notation choices. ♯/♭ become words ("C sharp"). `spoken_letter_names` (`res/values*/speech.xml`, not translated) picks how letter names are said: `words` ("C sharp"), `dutch` (cis, des, es, bes; b, not h) or `german` (Cis, Des, Es, As, B for B♭, His; naturals as written, so the German notation's H is said "H"; speech never changes which note a name means, so English letters picked in German still say "B" for B). Solfège keeps the sign as a word ("Sol kruis", "Mi mol"), and `spoken_solfege` spells the syllables the way the language writes them so TalkBack pronounces them right (French Ré, Portuguese Dó Ré Fá Lá, Arabic دو ري مي; the screen still shows Do Re Mi). Polish says letter names the German way (cis, es, b, h). A new language sets these two only if it differs from the default. The octave is the number on screen ("cis 4"). UI tests check Dutch with `DeviceConfigurationOverride.Locales`, which doesn't reach popups or the panel's window, so the Dutch panel is checked on the phone.
- **Labels:** strings read "A 2" (on every instrument, "F sharp 1" on an 8-string) plus "selected" / "Locked" and the lock action, and the long-press action "Play A 2" (while a tone sounds: "Playing" and "Stop the tone", and the hint "Playing A 2"); the navigation bar's Instrument item says "Instrument, Guitar, Standard", "double-tap to change instrument or tuning"; in the panel the title is a heading, instruments are radio buttons and tunings say their name and strings ("Half step down, E flat, A flat …"); the A4 slider reads "442 Hz". Settings rows are whole-row radio buttons and switches.
- **Large fonts:** the tuner body scrolls when taller than the screen (each pane on its own in two-pane). The 112-unit note name is in dp, so it doesn't grow further; string labels follow the font scale up to 1.3× (fixed 48 dp circles), and shrink further where a name would not fit its button. Squeezed 8-string rows give each button a touch area narrower than 48 dp (41 dp on a 360 dp phone), the only touch targets below 48 dp. A UI test checks every control is reachable at 2× font.
