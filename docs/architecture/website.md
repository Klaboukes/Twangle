# Website

Twangle's small public site (Phase 54): what Twangle is, how each tool works, and help for common problems, so a review or an email can be answered with a link. It makes the app's promise too: free (GitHub Pages, no server), no tracking, no cookies, no forms (the home page's one checkbox only plucks the logo again and sends nothing), no JavaScript, and **nothing loaded from another site**.

## Where it lives
- **Address:** https://klaboukes.github.io/ (Dutch at `/nl/`), GitHub Pages of the public repo `Klaboukes/klaboukes.github.io`, served from its `main` branch. That repo holds only the built pages; nobody edits it by hand.
- **Source:** `website/` in this repo, so a change to a tool updates its page in the same pull request (CLAUDE.md, *Conventions*).
- **Privacy policy:** stays where Play and the app link to it, https://klaboukes.github.io/twangle-privacy/ (Dutch `nl.html`), in its own repo `Klaboukes/twangle-privacy` (`scripts/publish-privacy.sh`, ARCHITECTURE.md §9). GitHub serves a project repo's pages under the user site's address, so the site links to it as `twangle-privacy/`, and the site itself must never have a `twangle-privacy` folder (the publish script refuses one). Its page frame is ours too (`website/privacy-layout.html`, copied there as `_layouts/default.html`): the GitHub Pages theme's own frame loaded a script from cdnjs.cloudflare.com, so the policy's page now keeps the site's promise as well. The policy has a section on the website itself (no cookies, no tracking, no scripts, nothing from another site; GitHub, the host, sees visitors' addresses as any web host does).
- **Linked from everywhere** (Phase 54): the app's About page has a *Help and website* row that opens the home page in the phone's browser, the Dutch one when the app is in Dutch ([Lifecycle and settings](lifecycle.md), *About*; the app keeps no `INTERNET` permission); the Play listing's website (`contact-website.txt` in `playAppDetails`, `app/build.gradle.kts`, sent with `scripts/release.sh listing`) is the home page, while the privacy-policy address in Play's *App content* stays the policy's own; README.md links it. A move to a domain of Twangle's own changes these four places too (Phase 91): About's row (`Website.kt` in `:feature:settings`), the listing's `contact-website.txt`, README.md and the privacy policy (PRIVACY.md and PRIVACY.nl.md, then `scripts/publish-privacy.sh`).
- Pages link to each other only with relative links, so moving to a domain of Twangle's own later (Phase 91) is a setting on the repo, not an edit.

## Pages and the frame
- `website/pages/<language>/<page>.html` is the inside of one page's `<main>`, plain HTML, with a header comment: `title`, `description` (the search snippet) and `nav` (which top-bar link to mark as the current one), and on a tool page `group` (`tuning`, `listening`, `practice` or `more`, its group on the home page, which colours the page; `build.py` refuses any other), on the home page `layout: full` (each section brings its own `.wrap`, so the stage runs the window's full width). `{play}` stands for the Play link, `{root}` for the way back to the site's root (`""` or `../`), `{coffee}` for the owner's Buy Me a Coffee page (*Buy me a coffee* below) and `{hero}` for the large plucked logo (`website/twangle-hero.svg`).
- `website/build.py` (Python standard library only, `python -I website/build.py [output]`, default `website/build/`, git-ignored; it empties the output first, so it refuses any other folder that isn't new, empty or one it built before) wraps each page in the shared frame (in the app's face, Nunito, since Phase 79: `website/static/nunito.woff2`, its Latin letters and weights cut from the app's `nunito.ttf` with `python -I -m fontTools.subset <Nunito[wght].ttf> --unicodes="U+0000-00FF,U+0131,U+0152-0153,U+02C6,U+02DA,U+02DC,U+2000-206F,U+20AC,U+2122,U+2212" --layout-features="kern,liga,calt,ccmp,locl,mark,mkmk" --flavor=woff2`, about 34 KB, its licence beside it as `nunito-OFL.txt`): head, top bar (Twangle, since Phase 79 the icon beside the name, `website/twangle-icon.svg` from `scripts/launcher-icon.py` and `website/twangle-name.svg` from `scripts/wordmark.py`, as the app's About page; the icon plucked by CSS when the page opens and when the pointer comes onto the name or it is tapped, played to the end even if the pointer leaves at once (a second copy of the harmonics, shown on hover and held for the pluck's length by delayed discrete transitions; browsers from 2023 and older pluck only as the page opens), at rest with reduced motion; then Tools, Help, Privacy, the other language), footer (*Made by one person. Free forever.* and, once the owner has a page, the *Buy me a coffee* link, then Help, Privacy, the other language, the contact email, Google's trademark line for the badge). The frame's own words are in `WORDS` in that file, per language. A link to a page that doesn't exist yet stays out of the frame (Help appears once `help.html` does), and a tool card on the home page (`<div data-page="tuner.html">`) stays a plain box until its page is written, then becomes a link with an arrow.
- `website/static/` is copied beside the pages: `site.css`, `img/` (the app icon, Google's badges), `shots/<language>/`. The output is plain HTML with a `.nojekyll` file, so GitHub serves it as it is.
- **Look** (Phase 83, 2026-11-06; built straight away at the owner's word, with no review or mock-up first, the logo large as asked; the look before, from `docs/design/website-preview.html`, is in [history](history.md)): 2.0's one look, Ink (`StylePalettes.kt`), light or dark as the visitor's device is set, in Nunito; cards on soft shadows with no hard borders, as the app; one column at phone width with no sideways scroll (`overflow-x: clip` on the body, so nothing on the stage's edges can widen the page), more side by side on wider screens. **The logo's three colours run through the site:** Ink's amber, blue and green are the logo's whole string, halves and thirds, so each group of tools has one, drawn as that harmonic's small mark (n lobes of sin(nπu), CSS masks in `site.css`): *Tuning* amber (the whole), *Listening* blue (the halves), *Practice* green (the thirds), *Instruments and more* all three in grey. The home page's group headings carry it, its cards' arrows and hover ring, and on a tool page (its header's `group`) the crumb, the numbered steps, the *For the curious* box and a soft wash at the page's top. The light amber is a shade deeper than the app's (`#A86400`), so white numbers on it stay readable.
- **The home page** (`layout: full`), section by section: **the stage**, dark in both themes (Ink dark, the background the logo's colours were made for; the top bar sits on it, without its own icon and name, as the banner below is them), with a banner in the middle: the logo (`website/twangle-hero.svg`) and the name beside it (`website/twangle-name.svg`, `{name}`), sized by the logo's height (48 to 120 px, about 5.4 times that wide in all, so it fits a 320 px phone), the name's capitals 0.6 of that tall and standing on the logo's string, so the halves and the thirds dip below it as the g's tail does. The owner had the logo alone, up to 560 px wide, made into this banner on 2026-11-07 ("a bit too big"), and the hairline of the string running out to the window's edges went with it, as it would have crossed the name. The logo is the harmonics on their own, cropped to themselves, plucked by `scripts/launcher-icon.py`'s own swing (`website_hero()`: the opening screen's maths, 1.8 s instead of 1 s, after 150 ms) as the page opens, with a soft glow under its string (three rings spreading in the harmonics' colours were taken out at the owner's word, the same day); the name stays still; then the headline, the line under it and Google's badge arrive. A tap (or click) on the banner plucks it again, and again, with no script: the mark is the `<label>` of a hidden checkbox (`.pluck`, out of the tab order and hidden from TalkBack with the whole mark, as it is only decoration), and each toggle switches every animation to its twin of another name (`th-…` and `th-…b`, `glow` and `glow-b`), which starts it over. Showing a second hidden copy, as the top bar's icon does on hover, doesn't do it here: the browser keeps a hidden SVG group's animation running, so it would show up finished. No hover pluck, so the logo stays still while someone reads, and nothing on the stage says it can be tapped: an easter egg (owner, 2026-11-07), hinted at only by the story's last line. With reduced motion it stands in its resting pose (the icon's), with no glow. Then the four promises (each with a check in the in-tune green), the tuner's screenshot beside *Tune any instrument* (the instruments, the word under the meter and the screen easing from amber to green, TalkBack, the vibration guide and the 36 languages, links to the tuner's and the instruments' pages), *The tools* (a line on the way round the app: the three tabs Tune · Metronome · Practice, Practice's list with the one used last, Settings behind the gear at the top left; then the four groups), *A look inside* (four screenshots), **the story** (*Why I made Twangle*, the owner's reasons in their own voice: the popular tuners' ads, subscriptions and data, the tuner they wanted, made with Claude; and the name and the logo explained, a twang being a plucked string ringing, as About says, the logo its first three harmonics; a card with the three colours along its top, `id="story"`), and the end, on the stage again: *Ready when you are*, the badge once more and the coffee line.
- **Tool pages** (the mock-up's tuner page is the model), one per home-page card, in the cards' order: `tuner.html`, `strum-check.html`, `12th-fret-check.html`, `chord-name.html`, `pitch-trail.html`, `metronome.html`, `chords.html`, `scales.html` (the drone too), `capo.html`, `ear-training.html` (its three exercises, what is asked, no scores kept, the microphone only for Play it back), `instruments.html` (the instruments and tunings, lowering, own tunings, the 12-string's courses, the banjo's short string, which tools work where), `left-handed.html`, `widget.html` and `watch.html` (the watch app: the tuner, its tap, the vibration guide's switch, the tile and the watch-face shortcut; its metronome, Phase 80, in a *Coming soon* section until its switch is on in release builds, the tile's Metronome button with it). Each has a crumb (Tools · Tuning, Listening or Practice), a lead, steps, short sections, a fold-out *For the curious* part (`details.curious`) where it helps, and links to the tools before and after it in the home page's order (`.nextprev`; the first and the last, the tuner and the watch, lead back to the tools). With a screenshot it sits beside the words (`.tool`); without one the page is one column (`.tool.solo`); a screenshot on its side goes across the column (`img.wide`). Pages say where to find a tool and walk through it, using the app's own words in italics. A tool still off in release builds (its `ToolSwitches` switch, [Threading and performance](performance.md), *Release build*) isn't walked through yet, as players can't find it: its page, or its tool's page, says in a short *Coming soon* section what it will do, and the steps come when it goes live, as Ear training's page did and the speed trainer's section on `metronome.html` did (Phase 62, 2026-10-31).
- **Help** (`help.html`, the mock-up's help page is the model; not in the tools' `.nextprev` chain, it is reached from the top bar and the footer): short answers as questions that fold open (`<details>`), grouped by topic (the microphone, tuning, the metronome, the app), the contact email at the end (`.ask`). Each answer's first paragraph has an id in English in both languages (`help.html#octave`, `nl/help.html#octave`), so a review or an email can be answered with a link that opens that answer (a browser opens a closed `<details>` to show the target inside it; `scroll-margin-top` keeps its question in view). The answers come from the app's code and strings, not from what a tuner usually does: the permission prompt's steps, the octave rule of Auto mode and the low-note window, the metronome stopping when its screen goes, the 3-minute screen rule, clearing storage to reset. New answers come from the weekly reviews (Phase 91) and the testers, in English and Dutch.
- **Facts stay true to the app:** names of instruments and tools as the app's `strings.xml` has them (in Dutch too), numbers from the code (e.g. the metronome's 30 to 250 BPM, `ClickTrack`). Pages explain ideas and walk through each tool rather than every button, so they stay true as the app changes.

## Nothing from another site
`website/build.py` checks the built output and fails, naming each problem, when:
- a page or stylesheet would load something from another host: any `src`, `srcset`, `poster`, `data` or `background` attribute, any `<link href>` (stylesheets, icons, fonts), a CSS `url()` or `@import`, in `site.css`, a `<style>` or a `style=""`, pointing at a URL with a scheme (`https:`, `http:`) or at `//host`; `data:` stays on the page and is allowed;
- a page has a `<script>` (the site works without JavaScript);
- a link inside the site leads to a page or file that isn't there, or to an `#id` the page doesn't have (`twangle-privacy/` is the one known exception, served by its own repo);
- a page exists in one language and not in another.

Plain `<a href>` links to other sites (Google Play, the email address) are allowed: they only open when the visitor taps them. Google's badge is a local copy for the same reason. To see the check work, add `<link rel="stylesheet" href="https://example.com/a.css">` to a page and build: it fails.

## Buy me a coffee
The owner asked for a *Buy me a coffee* link (2026-10-28): the app stays free with nothing to buy in it (hard rule 9), and the website is where a player who wants to can give something. `COFFEE_URL` in `website/build.py` is the page's address, empty for now (below). While it is empty nothing shows, as Help stays out until its page exists. Once it is set, the link is in the footer of every page, right after *Made by one person. Free forever.* (`coffee` in `WORDS`: *Buy me a coffee*, *Trakteer me op een koffie*), and the home page ends with a short box (`<p class="support" data-coffee>`, with `{coffee}` for the address) that `build.py` leaves out until then. It is a plain text link, so the site keeps its promise: Buy Me a Coffee's own button and widget are an image and a script from its servers, and the check above would refuse them. The app itself doesn't link the page: About's *Help and website* row opens the site, and that is enough. The first page was https://buymeacoffee.com/klaboukes, but Buy Me a Coffee pays out through Stripe, which requires a KvK number from every Dutch creator (2026-10-28). The owner chose Ko-fi, paid out to a personal PayPal account, and the link stays off the site until that page exists, after launch (ROADMAP.md, Phase 91): the mechanism stays, only `COFFEE_URL` and this paragraph change.

## Languages
English at the root, Dutch in `nl/` (`LANGUAGES` in `build.py`); every page exists in both, with the same file name, and the language link goes to the same page in the other language. On a phone the language link is in the footer only, to keep the top bar on one line. The other 14 app languages come after launch (Phase 91): add the folder to `LANGUAGES`, its frame words to `WORDS`, a Play badge in that language, its screenshots, and translate each page. Dutch is natural and short, in the app's own words (*Strumcheck*, *Toonlijn*, *Bourdon*).

## Publishing
The pages describe 2.0 since it landed on `main` (2026-11-06; until then they were written on the `v2` branch, unpublished, while the site showed 1.1); they go live with the next `scripts/publish-website.sh` (Phase 76). `scripts/publish-website.sh`, after a change to `website/` has landed on `main`: it fetches and builds `website/` **as `origin/main` has it**, never the folder it runs in (Phase 90: run from a worktree or a branch, it used to put unmerged text on the public site), unpacked with `git archive` into a temporary folder by `scripts/main-export.sh`, which names the commit and notes when the folder's own copy differs; it checks the site (a failed check stops it), clones `Klaboukes/klaboukes.github.io`, replaces its contents with the build (so a removed page goes too), and commits and pushes only when something changed, with GitHub's no-reply address (`816876+Klaboukes@users.noreply.github.com`, never a personal one: the repo is public). GitHub Pages shows the change within a few minutes. The repo was made public with GitHub Pages on its `main` branch (2026-10-27). `--dry-run` does all of that but the commit and the push, and lists the files that would change. `scripts/publish-privacy.sh` (and its `--dry-run`) takes the policies and `website/privacy-layout.html` from `origin/main` the same way.

To look at the pages before publishing: `python -I website/build.py`, then `python -I -m http.server 8754 --bind 127.0.0.1` in `website/build/`, and open http://127.0.0.1:8754/ at phone and desktop width.
